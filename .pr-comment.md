## What changed

**One catalog.** `packages/sem-schema` is replaced with the upstream package verbatim (`diff -r` empty against `schema-poc-1` HEAD `c56b397`, its 314 jest tests green). That brings `formats.json`, the `jsonlogic` format and the json keyword, so `enum`, `object`, `array` and `jsonlogic` now validate instead of being rejected as unknown formats. `lib/formats.ts` exports `FormatName`, `isFormatName()`, `formatType()` and `isNumericFormat()` off that file and nothing else hand-writes a format name.

**One registry.** `controls.ts` is `Record<FormatName, FormatEntry>`, so a format the catalog gains fails `tsc` until it has an entry. The entry absorbs five hand-written format lists that lived in four files, two pairs of which had already drifted: the form's and the grid's width buckets, the empty-to-null list, the JSON parse-on-submit branch, and the grid/skeleton column skip (which named `markdown` — not a catalog format, so nothing could ever have produced it).

**Strict resolution.** `assertSupportedFormats()` runs at the top of `SchemaForm`'s render and throws an `appError` naming the first offending field and listing all of them in `details`. There is no type fallback and no `InputText` fallback: those are how an `int32` got a free-text editor and an `enum` lost its picker, and the user then saved through it.

**Twelve formats gained a control.** New: `InputUrl`, `InputPassword`, `InputFile` (`binary`/`byte`) and `InputJsonPointerUriFragment`. Retargeted: `InputNumber` takes `int32`/`int64`/`float`/`double`, `InputJson` takes `jsonlogic`/`object`/`array`. On the tenant today that is 44 fields — 36 of them `int32` — that were rendering as text boxes.

**Unicode pairs merged.** `email`+`idn-email`, `hostname`+`idn-hostname`, `uri`+`iri`, `uri-reference`+`iri-reference` are one control each; the four IDN duplicates are deleted and their cases moved into the kept tests.

**Defect fixes** from the review: the cmdk keyboard highlight was being overridden away (WCAG 2.4.7); the four CodeMirror controls now share the form's field surface and carry the field `id` on `.cm-content`; `InputDate` was a day early west of Greenwich; a nullable reference's foreign key was submitted as a string because a union `type` never equalled `'integer'`; api-select's loaders and error region got `role="status"`/`role="alert"` and its skeleton moved out of the options list, where it had been announcing three selectable results that did not exist; `ErrorPage` now takes the boot overlay down.

## Things worth a second look

**The `Depends on` section of the plan was stale.** It said the backend must first send `format` on every field. That landed in semantius `b0db26f` (2026-09-15) and the test tenant runs it: across all 33 tables `get_schema` returns 0 fields without a format, and `fields.format` offers the same 44 names in the same order as `formats.json`.

**Two findings recorded in `formatRoundTrip.test.ts`, written against the live tenant.** Posting base64 into a BYTEA column answers **201**, not an error — Postgres reads it as its own escape format and stores those ASCII bytes, so a wrong encoding is silent corruption rather than a failed save. And an INTERVAL column accepts ISO 8601 on write but hands back `1 day 02:00:00`, so `InputDuration` displays a value it did not write and its own placeholder says is wrong. Per the plan that one is **reported, not patched** — the fix is a decision about which representation is canonical, and it is yours.

**`type="email"` was corrected for a different reason than the plan gave.** Chromium's punycode rewrite is real (measured via `execCommand`) but fires only on genuine editing, never on the value-setter path userEvent drives — so a test for it passes under `type="email"` too and could never fail. It is deliberately not asserted. What does fail is `validity.typeMismatch` on a non-ASCII local part, which is what holds the input type down. `type="url"` turned out to neither rewrite nor reject an IRI, so `InputUri`/`InputUrl` are `type="text"` for a different reason again: native constraint validation would fight sem-schema's and block `View.tsx`'s native `form={FORM_ID}` submit with a browser bubble.

**A hang the strict throw would have introduced.** A render throw unwinds the subtree before its effects commit, so `/form-playground`'s own `hideAppLoader()` effect never ran and the error page rendered behind the boot overlay. `appLoaderInvariant.test.ts` does not catch this — it scans for a top-level `return null`, not a throw. `ErrorPage` now calls it.

**Lint config.** `inputMode`, `width`, `emptyValue`, `format`, `autoCapitalize` and `autoCorrect` were added to lingui's `ignoreNames` (typed unions of identifiers, the same category as `type` and `variant` already there) and four narrow shape-based `ignore` patterns for a URL scheme, a UTC designator, an `Intl` unit and a PostgreSQL escape prefix. Net effect on the ratchet: **114 files / 610 suppressions → 92 / 557**.

Two British spellings remain in the diff, both inside the verbatim `packages/sem-schema` copy. Fixing them here would break the `diff -r` gate and be reverted by the next refresh; they belong upstream.
