## What changed

**Commit 1: rename and documentation. No behavior change.** `View` → `EntityView` (file, export, props type `EntityViewProps`). The resolver's fallback path and export name, the one suppression key, and the comment mentions follow. `views/README.md` is now the one description of the entity-view architecture: the route, the resolver and its naming rule, what `EntityView` owns and delegates, the customization contract (`EntityViewCustomization`), how to add an override, and how to test one. The `CONTEXT-MEMORY.md` section it replaces cited files that do not exist.

**Commit 2: the delete confirmation.**

- `DataTableView` takes `renderDeleteConfirmation(props: DeleteConfirmationProps)`, and `EntityView` forwards it. The grid keeps the mutation, refetch and toast; the override only decides which dialog is shown.
- `admin/Modules.tsx` swaps in `ConfirmDeleteModuleDialog`. Step 1 is the cascade warning. Step 2 needs the module's `module_slug` typed exactly, and Enter works once it matches. An empty slug fails closed, because the model requires no field of `modules`.
- The slot is keyed per open, so every Delete starts clean at step 1. It is not unmounted to close, so Base UI's closing transition runs and `ModalInert` takes `inert` off `#root` before focus returns. Unmounting instead would queue the focus call while `#root` is still inert. `useConfirmDelete` keeps the item through the close for this.
- **A pre-existing focus bug, fixed because this feature depends on it:** keyboard focus on a row's "..." button was lost whenever the grid re-rendered. Every cell is rendered from a column function, and the columns memo depended on values that were new on every render: the `useConfirmDelete` object, and `EntityView`'s inline `onEdit` / `getRowHref` / `excludeColumns` (it re-renders on every router-state change). A diagnostic test measured the focused button being replaced about 110ms after it was focused. Those values are now stable, and `admin/Users.tsx`'s `getRowMenuItems` too.

**Tests.** There are three new browser-project files, all against the real tenant with no substitutions:

- `ConfirmDeleteModuleDialog.test.tsx`: the dialog's rules.
- `admin/Modules.test.tsx`: the override end to end. It deletes a real fixture module by typing its slug, checks that Cancel returns focus to the row's menu button, and checks that the next Delete starts at step 1.
- `EntityView.test.tsx`: the generic dialog is unchanged. This is the first test of the delete path.

The `modules` fixture and `arrowTo` move to `src/test/` so these files can share them. `radix-ui` joins `optimizeDeps.include`, because these are the first browser tests to mount the full grid, and their first run discovered it mid-run and reloaded the page.
