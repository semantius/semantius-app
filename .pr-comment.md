## Why

`lingui/no-unlocalized-strings` checks every string literal in every file and cannot tell a column name from a sentence. It was carried by ~250 lines of `ignore` / `ignoreNames` / `ignoreFunctions` configuration plus `eslint-suppressions.json`, and it forced workarounds into the code. Linting only JSX text is the common practice: `eslint-plugin-i18next` defaults to it, and it works with any i18n library despite its name.

| Rule | Strings flagged on `src` (tests, `charts/`, `ui/` excluded) | Of which text |
| --- | --- | --- |
| `lingui/no-unlocalized-strings`, without the suppressions file | ~550 | ~8 |
| `i18next/no-literal-string`, default `jsx-text-only` | 1 | 1 ("Semantius UI", now `t()`) |
| `i18next/no-literal-string`, `jsx-only` (rejected) | 28 | ~4 |

`jsx-only` also checks attributes, but it validates every literal with a JSX ancestor, `.map()` callbacks included, so it reports identifiers like `${size}px` and `inputMode = 'hidden'`. Not linted by design: attributes such as `placeholder` / `aria-label`, and strings outside JSX (a toast message, a `{ label }` object).
